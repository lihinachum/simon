# MILESTONES — Simon

מסמך אבני דרך לפיתוח משחק Simon, על בסיס `PRD.md`, `ARCHITECTURE.md` ו־`DESIGN.md`. היעד הוא אתר Mobile-first בעברית (RTL), המותקן כ־PWA, עם שני מסכים בלבד וללא Backend או Database. כל אבן דרך מסתיימת בתוצר עובד שניתן להדגים ולאשר באופן עצמאי.

## 1. בסיס הפרויקט ומסך הבית האינטראקטיבי

**מטרה:** להקים מוצר Frontend הניתן להרצה ולבדיקה בטלפון, עם מבנה המסך והשפה החזותית המאושרים.

**מה יש לממש:**
- יצירת פרויקט React + TypeScript + Vite, Git Repository ב־GitHub, וסקריפטים ל־Development, Type Check, Tests ו־Build.
- יישום מסך הבית בגישת Mobile-first בעברית ו־RTL, לפי ה־Wireframes, ה־Style Guide וה־Mockups: כותרת Simon, הנחיה, לוח עגול המורכב מארבעה רבעים (אדום, ירוק, כחול, צהוב), כפתור **"התחל"** במרכז וכפתור אודות בחלק העליון.
- יישום תגובה חזותית בסיסית לנגיעה באזורי הצבע והנחת תשתית רכיבים/סגנונות משותפת למסכים הבאים, בלי להפעיל עדיין משחק מלא.
- הכנת סביבת בדיקות Vitest ו־Playwright בהתאם ל־Architecture.

**תוצר מצופה:** מסך בית מעוצב, עולה מקומית בדפדפן במידות טלפון, עם רכיבי מגע ברורים ו־Build תקין; לוגיקת משחק עדיין אינה מלאה.

**Definition of Done:**
- `npm run build` ובדיקת TypeScript מסתיימים ללא שגיאות; בדיקת Smoke בסיסית עוברת.
- מסך הבית נראה ועובד בפריסת מובייל RTL, ובו ארבעה אזורים במיקומים ובצבעים שהוגדרו; אין מסכים או תפריטים שלא אושרו.
- כפתור **"התחל"** ואזורי הצבעים מגיבים לנגיעה ללא שגיאות Runtime; אין מצג שווא של משחק שלם לפני מימושו.
- הקוד קיים ב־GitHub וניתן להרצה לפי הוראות קצרות ב־README.

## 2. משחק Simon מלא מקצה לקצה

**מטרה:** לאפשר למשתמש להשלים משחק שלם — התחלה, הדגמה, שחזור, התקדמות, הפסד או ניצחון ומשחק חדש.

**מה יש לממש:**
- Game State Machine ויצירת רצף אקראי חדש לכל משחק: צבע יחיד בשלב 1 והוספת צבע אחד בכל שלב עד 10; הדגמת כל הרצף בקצב קבוע עם הבהוב וצליל ייחודי לכל צבע באמצעות Web Audio API.
- מעבר מבוקר מהדגמה לקלט; התעלמות מנגיעות בזמן ההדגמה; הבהוב וצליל בלחיצות המשתמש; בדיקה לפי סדר הרצף ללא Timeout, תוך מניעת תקלות בלחיצות מהירות.
- הודעת הצלחה קצרה ומעבר אוטומטי לשלב הבא; סיום מיידי בלחיצה שגויה; ניצחון לאחר שלב 10 בלבד.
- במרכז הלוח הצגת השלב הנוכחי מתוך 10 במהלך המשחק; בהפסד או בניצחון הצגת הודעה, ניקוד לפי **שלבים שהושלמו** וכפתור **"משחק חדש"**. הוספת צליל שגיאה בהפסד ואנימציה וצליל חגיגיים בניצחון.

**תוצר מצופה:** אפשר לשחק משחק Simon מלא במסך הבית עם אורות וצלילים, לקבל תוצאה ולהתחיל משחק חדש בלי רענון.

**Definition of Done:**
- בדיקות Vitest מאמתות אורכי רצף 1–10, הוספת צבע יחיד, נכונות/שגיאה בכל צעד, מעבר אוטומטי, הפסד בשלב 1 עם 0 נקודות, הפסד בשלב 5 עם 4 נקודות וניצחון בשלב 10 עם 10 נקודות; אין שלב 11.
- בדיקת Flow מוודאת שהצבעים אינם קולטים לחיצות בזמן הדגמה ושאפשר להשלים משחק ולהתחיל חדש.
- כל הפעלה תקינה של צבע מדליקה אותו ומשמיעה צליל מזוהה; אפקטי הסיום נשמעים/נראים ונבדקים גם בטלפון אמיתי, בהתחשב במדיניות השמע של הדפדפן.
- הקצב נשאר קבוע בכל השלבים; המתנה ארוכה בין לחיצות אינה גורמת להפסד; לחיצות מהירות אינן מדלגות על בדיקה או יוצרות סיום כפול.

## 3. מסך אודות, ניקוד מקומי וניווט

**מטרה:** להשלים את חוויית שני המסכים ולשמר תוצאות של משחקים שהסתיימו בלבד.

**מה יש לממש:**
- מסך אודות לפי העיצוב: כותרת, תיאור Simon, הוראות קצרות, **"שיא אישי"**, **"תוצאה אחרונה"**, וכפתור **"חזרה"**; תוכן עשוי להיגלל במסגרת מסך המובייל.
- ניווט מקומי בין מסך הבית למסך אודות, ללא מסך שלישי וללא ספריית Routing; מעבר לאודות באמצע משחק נוטש את המשחק ללא שמירת תוצאה וחזרה מציגה מצב פתיחה.
- Score Store עם שני נתוני ניקוד בלבד ב־Local Storage (`bestScore`, `lastScore`): עדכון תוצאה אחרונה בסיום, עדכון שיא רק כשנשבר, תצוגת מצב ללא תוצאה וטיפול בקריאה/כתיבה חסומה או פגומה.
- בהתאם ל־DESIGN, שיקוף הנתונים גם בכרטיס הניקוד שמופיע בתחתית מסך הבית, בלי לשנות את העובדה שהצגת הניקוד במסך אודות היא דרישת PRD מחייבת.

**תוצר מצופה:** שני מסכים מעוצבים, ניווט תקין, נתוני ניקוד אמיתיים שנשמרים בין רענונים ואינם משתנים עקב משחק שננטש.

**Definition of Done:**
- ניווט בית → אודות → בית עובד; מסך אודות מציג את כל פרטי התוכן והניקוד הנדרשים.
- לאחר הפסד או ניצחון, `lastScore` מציג את תוצאת המשחק שהסתיים ו־`bestScore` נשאר שיא מקסימלי גם לאחר תוצאה נמוכה יותר.
- רענון או מעבר לאודות באמצע משחק לא משנים אף נתון שמור; רענון מאפס את המשחק הפעיל אך לא את התוצאות השמורות.
- כשאין נתונים או כשה־Storage אינו זמין/תקין, המשחק אינו קורס ולא מוצגים ערכים שגויים כנתוני אמת.
- בדיקות Vitest ו־Playwright מכסות את שמירת הניקוד, הניווט ונטישת המשחק; הפריסה נבדקת במידות מובייל ו־RTL.

## 4. חוויית מובייל רציפה ו־PWA

**מטרה:** לאפשר משחק אמין בחזרת משתמש מאפליקציה אחרת ולתמוך בהתקנה כ־PWA ללא שינוי בלוגיקת המשחק.

**מה יש לממש:**
- טיפול ב־Page Visibility ובמעברי רקע/נעילת טלפון: עצירת שמע ותזמונים בזמן יציאה לרקע, חזרה לאותו מצב קלט, או הדגמת הרצף מחדש מתחילתו אם נקטעה; מצב המשחק נשמר בזיכרון בלבד.
- מניעת Callback ישן או צליל מאוחר לאחר השהיה, נטישה או התחלת משחק חדש, וחידוש שמע בהתאם למגבלות Safari/Chrome במובייל.
- הגדרת vite-plugin-pwa, Web App Manifest, אייקונים, Service Worker ו־Cache לנכסי האתר הסטטיים; שמירה על עברית/RTL וממשק זהה באתר ובאפליקציה המותקנת.

**תוצר מצופה:** גרסה שניתן להתקין בטלפון כ־PWA ולהמשיך בה משחק לאחר מעבר זמני לרקע, ככל שהמערכת משאירה את העמוד בזיכרון.

**Definition of Done:**
- חזרה מרקע באמצע שחזור ממשיכה מהמיקום הנכון; חזרה מרקע באמצע הדגמה מריצה את אותו רצף מחדש מתחילתו.
- אין כתיבת ניקוד בעקבות השהיה, ואין השמעות או מעברי שלב כפולים לאחר חזרה.
- ניתן להתקין PWA במכשיר/דפדפן תומך; Manifest ואייקונים נטענים, והאתר הנטען פעם אחת זמין ללא רשת במסגרת Cache הנכסים הסטטיים.
- בדיקות ידניות מתועדות ב־Chrome/Android וב־Safari/iOS להתנהגות שמע, מעבר לרקע/נעילה והתקנה, תוך ציון מגבלות דפדפן או מערכת הפעלה שלא ניתן לשלוט בהן (למשל סגירת האפליקציה ברקע).
- Build ובדיקות אוטומטיות של אבני הדרך הקודמות ממשיכים לעבור.

## 5. פריסה אוטומטית ואימות המוצר החי

**מטרה:** לפרסם את המשחק כאתר מאובטח ב־GitHub Pages, עם תהליך עדכון אוטומטי ואימות מקצה לקצה.

**מה יש לממש:**
- הגדרת GitHub Pages לפרסום באמצעות GitHub Actions מתוך אותו Repository; Workflow שמריץ התקנת תלויות, Type Check, Vitest, בדיקות Playwright המתאימות ל־CI, Build ו־Deployment ל־Pages רק לאחר הצלחה.
- התאמת `base`, נתיבי נכסים, Manifest, `start_url` ו־`scope` לנתיב האתר ב־GitHub Pages.
- בדיקת המסכים, צלילים, משחק מלא, ניקוד, ניווט, השהיה, PWA ורענון באתר שפורסם; תיעוד הפעלה בסיסי וכתובת האתר ב־README.

**תוצר מצופה:** קישור HTTPS ציבורי למשחק Simon המלא, והעלאת שינוי ל־`main` מפעילה פריסה אוטומטית ללא פעולת פרסום ידנית.

**Definition of Done:**
- ה־GitHub Actions Workflow מסתיים בהצלחה ומפרסם את `dist/` ל־GitHub Pages; שגיאה בבדיקות או ב־Build חוסמת פריסה של גרסה לא תקינה.
- כתובת האתר החי נטענת בטלפון ללא שגיאות נכסים או קונסול, ושני המסכים והתוכן בעברית RTL תואמים לעיצוב המאושר.
- אפשר להתחיל משחק, לנצח/להפסיד, להתחיל משחק חדש ולבדוק את התוצאות באודות; התוצאות שורדות רענון ומשחק פעיל אינו שורד רענון.
- Manifest, אייקונים, התקנה ועדכון נכסים פועלים בכתובת GitHub Pages בפועל; בדיקות מובייל חיוניות הושלמו ותוצאותיהן הוצגו למשתמש.
- שינוי מאושר נוסף ב־`main` מפעיל Build ו־Deployment אוטומטיים ללא העלאה ידנית.

## Development Execution Rules — הנחיות מחייבות ל־AI המפתח

1. **יש לפתח את ה־Milestones לפי הסדר המופיע במסמך.** אין לדלג על Milestone או להתחיל את הבא במקביל.
2. בסיום **כל** Milestone יש לעצור את הפיתוח, להציג למשתמש את התוצר העובד ואת הדרך לבדוק אותו, ולדווח באופן מפורש על תוצאות הבדיקות מול כל סעיף ב־**Definition of Done**: עבר, נכשל או לא נבדק, בצירוף הסבר קצר במידת הצורך. אין לדווח על בדיקה כעוברת אם לא הורצה.
3. **אין להתחיל את ה־Milestone הבא ללא אישור מפורש של המשתמש.** אם תנאי השלמה לא מתקיים, יש לתקן ולבדוק מחדש לפני בקשת אישור.
4. יש להיצמד ל־`PRD.md` בדרישות ובהתנהגות, ל־`ARCHITECTURE.md` בהחלטות הטכניות ול־`DESIGN.md` במראה ובמבנה. אין להוסיף יכולות, מסכים או שירותים שלא אושרו.
5. אין בפרויקט Backend או Database ולכן אין צורך בסביבות Supabase, ב־Database Migrations או בניהול Secrets למערכת. הקוד מנוהל ב־GitHub; הפריסה תתבצע ב־GitHub Pages כפי שהוגדר.
